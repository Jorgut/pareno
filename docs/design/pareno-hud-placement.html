HUD 吸附位置：六种方案

问题：HUD 固定在光标上方。当文档从窗口顶部开始时，上方被标题栏/工具栏挤压；如果翻到下方，又会撞上输入法候选窗。下面基于已定稿的三键 HUD，比较六种吸附策略，先确定默认行为再改代码。

默认推荐：C 智能避让 备选：D 输入框吸附 保留：F 固定位置 不采用：B 简单下方翻转

为什么现在会被挡

新文档、Word 页面上沿、浏览器地址栏下方：光标离屏幕顶部只有几十像素，HUD 高 38px，加上间距放不下；强行放下会压住窗口工具栏或屏幕菜单栏。翻到光标下方，又会和输入法候选窗重叠。

设计目标

优先级：不遮输入法 > 靠近光标 > 不超出屏幕 > 不遮工具栏。顶部不够时不再硬翻转，而是换到光标侧边；网页输入框读不到光标时吸附输入框；所有位置都可被用户固定。

建议：默认做 C，D 作为自动兜底

不是简单“上/下翻转”，而是按空间和碰撞依次尝试，任何一步都不进入输入法候选区（光标下方约 48px、宽 260px 的区域）。

  1. 上方：光标上方 ≥ 38px + 12px 间距 → 放上方。
  2. 右侧：上方不够 → 放光标右侧，垂直居中对齐；右侧超出屏幕 → 换左侧。
  3. 输入框上沿：两侧都不够 → 用 AXFrame 把 HUD 贴在编辑区上沿。
  4. 固定停靠：仍无位置 → 底部/顶部停靠，并记住上次位置。
  5. 结果卡：始终吸附 HUD；HUD 在侧边时，卡片向另一侧或上方展开，绝不覆盖候选窗。

设置里保留四个选项：智能避让（默认）、始终上方、吸附输入框、固定位置。不做“始终下方”，因为它和中文输入法候选窗冲突。
