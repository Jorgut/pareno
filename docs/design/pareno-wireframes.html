PARENO · Design wireframe · 2026-11-14

PARENO 双端线框图

一个项目，两个端口：Obsidian 插件与桌面端写作工具。桌面端像输入法一样贴着光标，主按钮沿用插件里已经实现的「检查 / 翻译 / 解释」；两端的检查结果、修改方式与文案保持一致。

HUD = Heads-Up Display（抬头显示）。原指飞行员不用低头就能看到的信息层；这里指贴着光标、不打断输入的小工具条。

03 · 桌面端：解释模式

Explain only · 不写回
DESKTOP / EXPLAIN
任意 App 的输入框 · 想弄明白为什么
I very like this building.
Pareno Desktop 解释gpt-oss:20b×
原文I very like this building.
问题在哪

very 是副词，不能直接修饰动词 like。中文说“很喜欢”，英文要用 really like 或 like ... very much。

更自然的说法
I really like this building.
例句

She really likes the way the courtyard opens to the street.

复制解释关闭
三个按钮：266px

Spec

  • 解释 只解释，不写回原文：为什么错、更自然的说法、一个例句。
  • 适合“我知道不对，但不知道错在哪”的场景；语音输入后尤其有用。
  • 解释卡没有替换按钮，只有复制解释 / 关闭。
  • 三个按钮固定顺序：检查、翻译、解释；不常用任务仍收进 ⋯。
HUD 三键固定顺序 检查 · 翻译 · 解释 解释 = 只读模式 不自动替换

05 · 状态与吸附方式

Follow / Fixed / Empty / No permission
STATES

吸附光标 · 空闲

在任意输入框聚焦时出现在光标上方；离开输入框 1 秒后隐藏。

✓ 检查▤ 翻译≡ 解释

检查中

按钮变为进度状态，结果卡占位；仍贴着光标，不跳走。

◌ 检查中…▤ 翻译≡ 解释

固定位置

拖动左侧握把放到任意位置，记住坐标；不随光标移动。

✓ 检查▤ 翻译≡ 解释

无权限 / 无文本

明确说明缺什么，并给「打开辅助功能设置」；不静默消失。

⚠ 需要辅助功能权限
选中 / 光标在段落→ HUD 出现→ 点检查 / 翻译→ 结果卡→ 替换 / 复制

交互规则

  • HUD 不抢焦点；点击按钮不打断输入。
  • 检查中仍可继续打字；结果基于点击瞬间的文本。
  • 固定模式适合放在屏幕角落反复使用；吸附模式适合长文连续写。
  • 默认吸附；菜单里可切换并记住选择。
